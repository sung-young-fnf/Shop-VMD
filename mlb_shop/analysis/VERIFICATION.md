# 도면 분석·캡처 패키지 검증

## 범위

- 원본 PDF106페이지. 전체 렌더106개, 개요 시트7개, 상세 확대151개.
- 팀 파트별 전수 확인: 외관12 / 공간13 / 재료13 / 벽면37 / 중앙·서비스27 / 상층4 =106페이지. 모든 원본 페이지는 한 파트의 주 담당 범위에 포함된다.
- 상세 캡처: 외관18 / 공간18 / 재료21 / 벽면46 / 중앙·서비스40 / 상층8 =151개.
- 각 파트는 전체 담당 페이지 시각 확인표, 치수/재질/수량 근거, 제작 위임, 상충 사항, 캡처 manifest를 제공한다.

## 직접 실행한 검사

1. 원본 SHA-256을 다시 계산하여 추출 시 저장한 값과 일치함을 확인했다. 원본은 변경하지 않았다.
2. 전체 페이지 manifest의 페이지번호와 PAGE_INDEX의 행이1~106을 빠짐없이 한 번씩 포함하는지 확인했다.
3. 전체 페이지106개와 상세 PNG151개를 이미지 라이브러리로 열고 디코딩 무결성을 검사했다.
4. 상세151개 각각의 PDF 페이지번호, 크롭 범위(1191×842pt 안), 배율과 실제 이미지 픽셀 크기의 일치를 검사했다. 소수점 크롭 경계 렌더링의1px 반올림 차이만 허용했다.
5. 분석 문서와 캡처 README의 상대 링크가 실제 파일로 연결되는지 검사했다.
6. 총괄이 전체 개요7장과 주요 평면·재료표·카운터 원본을 직접 보았고, 각 담당은 자신의 모든 담당 페이지와 확대 캡처를 확인했다. 총괄은 손잡이(p017), 중앙 배치(p018), 천장 단면(p025), 후크(p093), 카운터(p069), 창고 물량(p106)의 최종 확대 캡처도 직접 열어 가독성과 치수선을 확인했다.
7. 독립 문서 점검에서 정문/중앙 집기 방향과 페이지 색인을 대조했다. 동일 로고의3000K/5000K 충돌이 총괄 요약에서 약화되는 문제를 본문과 CONFLICT-09에 반영했다. 손잡이를 야구공 스티치 반원형으로 명확히 하고 보 마감·정문 높이·DP-T2 높이 차이를 CONFLICT-10~12에 추가했다.
8. 공용 `skills/shop-drawing-analysis/SKILL.md`는 skill-creator의 quick_validate 검사에 통과했다.

최종 기계 검사 결과는 [validation-results.json](validation-results.json)에 기록한다. 팀 작업 이력은 `team_archive/`에 보존하며 원본 PDF와 별개다.

## 검증하지 않은 것

현장 실측, 실제 준공 상태와의 완전 일치, 시트별 최종 승인/개정 우선순위, 최신 상품·광고 아트, 전기 설계의 안전/용량 인증은 검증하지 않았다. 별도 사용자 JPG 전체를 사진 조사한 작업도 아니다. 이번 작업은 Three.js 코드 구현이나 하네스·브라우저 QA를 수행한 것이 아니다.

상충 치수와 색온도는 분석 실패를 숨긴 값이 아니라 원본의 지시 차이를 보존한 확인 대기 목록이다. 전체 캡처에 포함된 원본 연락처 등은 외부 공개 전 별도 검토가 필요하다.
