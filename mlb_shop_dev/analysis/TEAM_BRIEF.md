# MLB 성수점 도면 분석 공통 지침

## 목표와 범위

사용자 요청: 106페이지 준공도면을 구역별로 정밀 분석하여 매장의 외관, 내부 구성, 각 장소에서 Three.js로 구현할 항목을 한국어 문서로 정리한다. 필요한 도면 캡처를 `mlb_shop/reference` 아래 남겨 후속 제작 에이전트에 위임할 수 있게 한다. 이번 작업은 분석·증거 패키지이며 앱 구현은 하지 않는다.

## 원본과 도구

- 원본: `mlb_shop/reference/★M_성수점_준공도면_인테리어파크_250519 (2).pdf` (106페이지).
- 텍스트: `mlb_shop/analysis/source/pages/page-NNN.txt` (UTF-8).
- 기존 전체 페이지 PNG: `mlb_shop/analysis/source/pages/page-NNN.png`.
- 전체 개요 이미지: `mlb_shop/analysis/source/overview/sheet-01.png`~`sheet-07.png`.
- PDF 스킬을 읽고, 반드시 담당 페이지를 이미지로 확인한다. 텍스트만으로 도형·배치·색을 확정하지 않는다.
- Git Bash MCP를 우선 사용한다. `uv run --no-project --with pymupdf --with pillow python -X utf8`로 PDF 렌더링과 필요한 확대 영역 추출이 가능하다. 명령 출력은 공백을 정규화하고 범위를 제한한다.
- 원본 PDF와 사용자 JPG는 수정하지 않는다. 근접한 JPG는 보조 근거로만 사용하고 사용한 파일명을 명시한다.

## 담당 산출물과 캡처

각 담당자는 팀 상태에 지정된 `analysis/parts/<담당>.md`와 `reference/drawing_captures/<담당>/`만 수정한다. 다른 사람이 동시에 작업 중이며 다른 사람의 변경을 되돌리지 않는다. 보고서 편집은 apply_patch를 사용한다.

총괄은 전체 106페이지 PNG를 `reference/drawing_captures/pages/page-NNN.png`에 별도 배치하고 전체 페이지 색인을 만든다. 담당자는 이를 복사하거나 변경할 필요가 없다. 상세 캡처만 자신의 폴더에 만든다.

각 구역에서 실제 제작에 필요한 주요 평면·입면·단면·접합·마감·치수 영역을 PDF에서 확대 렌더링한다. 캡처는 최소 2배, 작은 주석은 3~4배 렌더링을 권장한다. 도면 제목만 남거나 치수선이 잘리는 무의미한 크롭은 금지한다. 확인용 썸네일만 전달하지 않는다. 파일명은 `pNNN_<component>_<view>.png`로 한다. 이미지 생성 도구가 아닌 PDF 원본 렌더링이다.

각 담당 캡처 폴더에 `manifest.json`을 둔다. 배열 항목은 `file`, `pdf_page`(1부터), `crop_pdf_points`([x0,y0,x1,y1], PDF 좌상단 원점), `render_scale`, `purpose`, `component_codes`를 포함한다. 이는 생성 데이터이므로 렌더링 명령에서 함께 기록해도 된다. 보고서에는 캡처 링크와 사용 목적, 확인한 담당 페이지 목록을 모두 남긴다.

## 분석의 기준

1. 담당된 모든 페이지를 확인하고 페이지별 제목·역할을 기록한다. 표제란 DRAWING NO.는 반복될 수 있으므로 항상 PDF 페이지 번호를 사용한다.
2. 공간별 위치는 우선 `p018 평면 기준 상단/하단/좌측/우측`으로 설명한다. 북쪽 화살표 없는 도면에 방위를 붙이지 않는다. 정문 위치와 출입·코어·피팅룸을 시각 대조한다.
3. 형상, 치수(mm), 높이, 마감 코드, 집기 코드, 도면 수량과 설치 위치를 구분한다. 상세도 부품 수량을 완제품 수량에 더하지 않는다. 불명확한 D/W 방향과 전체 치수는 추정하지 않는다.
4. 도면 명시 사실 / 이미지 관찰 / 분석 추론 / 미확인을 분리한다. 철거도·기존 존치·신설·임시 이벤트 메모를 최종 상태와 혼동하지 않는다.
5. 각 중요한 사실과 표 행에 PDF p.NNN 근거를 붙인다. 치수가 충돌하면 둘 다 기록하고 평면·입면·상세도 중 어떤 관점인지 설명한다. 파일명 날짜가 모든 시트의 개정일임을 가정하지 않는다.
6. 재료표와 상세도 간 마감·조명 색온도 충돌을 숨기지 않는다. 문서의 분홍·노랑 표시색이 실제 마감색이라고 단정하지 않는다.
7. PDF 속 업체 연락처나 개인 이름·전화번호는 분석 문서에 옮기지 않는다.
8. Three.js 항목은 구현 제안으로 표시한다. 필요한 오브젝트 계층, 재사용 가능한 집기 부품, 중요한 실루엣/재질, 선택적으로 단순화할 내부 구조, 선행 의존성과 확인 질문을 담는다. 최종 실측·시공 인증 문서가 아니다.

## 권장 보고서 구성

요약 → 공간/집기 상세 표 → 형태·치수·마감과 페이지 근거 → 구현해야 하는 부품과 재사용 관계 → 캡처 목록/위임할 파일 → 불확실성/상충사항 → 담당 페이지 전수 확인표.

팀 지침에 따라 중간 발견과 다른 담당에게 영향을 주는 내용을 영어로 메시지한다. 담당 보고서는 한국어로 작성한다. 완료 시 파일 경로, 캡처 수, 확인 페이지 수, 핵심 위험을 총괄에 보고한다.
