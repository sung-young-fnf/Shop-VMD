# 네이비 NY 모자 사례: M21N3ACP7701N

2026-09-08 DEV 구현에서 정리한 사례다. 공용 기본값이 아니라 이 SKU의 사진과 틀에 한정된 기록이다.

## 구현 연결

프로젝트가 함께 제공될 때 `mlb_shop_dev/src/products/caps/`의 다음 파일을 참고한다.

- `real-surfaces.ts`: 크라운·개구부·챙의 정규화 식과 곡면 패치.
- `real-details.ts`: 안쪽 밴드·테이프·봉제·버클. 사진에 있는 통기구의 추가 링은 제외.
- `photo-cap.ts`: 6패널 실제 틀과 별도 사진 투영 좌표.
- `photo-blend.ts`: 정면·후면·측면·디테일 사진 혼합.

이 파일들은 예제이지 스킬 실행 의존성이 아니다. 다른 프로젝트에서 경계를 넘는 import나 링크로 연결하지 않는다.

## 사진 좌표 예시

분석 좌표는 1368×1824 기준이며 원본 2000×2667과 구분한다. UV는 `(px/1368, 1-py/1824)`로 변환했다.

```text
sx = capPosition.x / .102
h = clamp((capPosition.y-.018)/.116, 0, 1)
sz = capPosition.z / .097
frontPx = (683+sx*405, 512+(1-h)*(440+88*sx*sx))
rearPx = (683-sx*395, 1237-76*sx^4-h*688)
sidePx = (890-sz*270, 1120-h*480)
```

혼합은 `abs(vec3(sx,h,sz))^6`을 사용하고 Y 가중치를 .2배 한 뒤 합으로 정규화했다. 이는 위치 기반 영역 혼합이며 normal 기반 triplanar와 다르다. 상단은 디테일 컷의 (830,340)부터 200×200 영역을 4위상으로 겹쳐 사용했다.

후면의 밝은 배경 제거는 후면·중앙·하단에만 한정했다. 네이비용 밝기 임계값은 흰 자수·다른 색상에 일반화할 수 없다. 후면 사진의 버클 영역도 모델 버클과 중복되지 않게 원단 영역으로 혼합했다.

크라운 정점의 렌더링 좌표와 사진 좌표는 서로 다르다. 후면에서는 사진의 개구부 경계를 실제 틀의 개구부에 재매핑했다. 이 기준 속성을 집기 메쉬 병합 후에도 보존해야 한다.

## 확인된 교훈

- 사진의 6개 통기구 위에 모델 링 6개를 추가하면 통기구가 이중으로 보였다. 추가 링을 없애고 사진이 담당하도록 한 버전을 검증했다.
- 단품이 정상이어도 서로 다른 attribute 구성을 병합하면 매장에서 오류가 발생할 수 있다. 실제 집기 배처로 검사해야 한다.
- 큰 곡면 패치 삼각형은 자수를 잘라 보이게 만들 수 있다. 분할과 면 내부 간격 검사가 필요하다.
- gallery-8이 확보된 뒤 내부 테이프·직조 라벨·리벳도 실제 사진으로 개선했다. 챙 아래쪽과 사진에 없는 구조는 여전히 추정이며 완전한 실측 복제품이나 재조명 가능한 스캔 에셋은 아니다.

## 증거와 한계

### DEV 매장 배치 보존 검증

후면 볼륨을 보정한 모자 형상·재질을 그대로 두고 실제 매장의 배치만 수정했다. 최신 매장 근거는 `mlb_shop_dev/evidence/cap-store-integration-20260908/ROOT-REVIEW.md`와 각 캡처의 소스 해시다.

- 벽면/타공판에서는 챙 최저점이 선반 아래 39.856mm에 있었다. 실제 변환 bounds를 지지면 위 1mm로 맞췄다.
- 쇼케이스의 부모 축척 `(2,.7,.55)`가 모자를 납작하게 만들었다. 의류 부모와 배치는 유지하고 모자만 비왜곡 부모로 분리했다. 선반 깊이에 맞추는 축척은 균일하게 적용했다.
- 실제 161개 모자(이 네이비 SKU 27개)의 상품 배정, 지지면·유리 간섭, 축 비율을 검사했다. 다른 5개 SKU를 이 네이비 사진 모델로 바꾼 것이 아니다.
- 실제 두 집기 배처의 정점별 XYZ 및 사진 좌표 대응을 검사했다. 위치 최대 차이는 약 1.20e-7m, 허용치는 3e-7m다. 의류 배치 해시는 1µm 좌표 양자화 기준 보존이며 부동소수점 비트 단위 동일성 주장은 아니다.
- 벽면·타공판·중앙·쇼케이스 근접 캡처와 전체 매장 확대·회전·구역 이동·보행·야간·천장 전환, 375/768/1280px 화면을 확인했다. 이번 짧은 Chrome 실행에서 오류와 context 이벤트는 없었다. 과거 context loss 원인의 해결이나 장시간/GPU별 안정성을 입증하지 않는다.
- 빌드 runtime은 `runtime-DWNXlbMN.js`, SHA256 `a79c28ee6eecf40655e70865dc3f4ffdc32b56f5bf0e1b15c42613f63f4d7d3a`다. 브라우저 검사는 LIVE DEV5175에서 대응 소스 해시를 기록했다. 운영본은 변경하지 않았다.

### 사용자 측면 재검토: 뒤통수 볼륨 보정

이전 다각도 검토의 뒤통수 통과 판정은 사용자가 지적한 측면 차이를 놓쳤다. 최신 근거는 `mlb_shop_dev/evidence/cap-rear-volume-20260908/ROOT-REVIEW.md`다. 전체 폭·높이와 챙 낙차만 맞아도 위·중간 뒤통수가 사선으로 깎이고 밑단이 뾰족하게 끝날 수 있다.

원본 gallery4의 불투명 네이비 경계를 여러 높이에서 읽으면, 1368폭 환산 기준 최대 뒤 폭은 y950 부근 x1206.6, 밑단 y1165에서는 x1171.7이다. 원본 2000×2667의 투명 RGB를 제외한 측정이며, 수동 카메라 정렬 결과를 제조 치수나 픽셀 완전 일치 점수로 부르지 않는다.

앞 반구의 기존 수식을 유지한 채 뒤쪽 Z 반경에만 완만한 가중치를 적용했다. 위·중간 뒤 어깨는 .55 지수로 채우고, 넓은 볼륨 항과 작은 .03 밑단 말림을 분리했다. .09로 끝만 크게 줄인 초기 후보는 뒤 도달 길이가 너무 짧아 재수정했다. 조절끈 깊이는 수정된 뒤 밑단에서 유도해 천 끝의 돌출을 막고 금속 버클은 외부 노출을 유지했다. 정면777개·챙861개 사전 좌표를 고정해 보존 여부를 확인한다.

아래의 이전 다각도 결과는 과거 단계다. 최신 수정의 완료 여부는 새 root 판정과 해당 소스 해시에 연결된 캡처를 확인한다.

### 다각도 반복 보정 (이전 측면 전용 수식을 대체)

`mlb_shop_dev/evidence/cap-multiview-20260908/ROOT-REFERENCE-REVIEW.md`가 원본 사진에 대한 root의 직접 판정 기록이다. 개별 `report.json`의 실행 성공은 외형 일치 판정을 대신하지 않는다. 최종 상태는 이 기록의 마지막 판정을 확인한다.

- 원본 gallery5 정면에서 챙 자유단 중앙은 양 끝보다 약 .117 크라운 폭만큼 높다. 전체 높이는 약 .90W, 로고 폭/높이는 약 .16W/.18W다. gallery4 측면의 챙 최저점과 뒤 밑단 차이는 약 .042 측면 크라운 폭이다. 모두 수동 사진 측정 근삿값이다.
- 정면 카메라 고도 .14rad, 측면 방위1.44rad/고도.06rad, 후면 고도.18rad, 사선 방위.64rad/고도.23rad를 선언하고 고정했다. 정면 로고 위치를 먼저 내렸다가 카메라 보정 후 너무 낮아져 사진 warp를 제거했다.
- X/Z radial 지수를 .65/.95로 분리했다. 부착 반폭 .82는 정면을 좁게 만들어 .91로 수정하고 앞끝 벌어짐과 횡방향 말림을 별도 항으로 추가했다. 이전 측면만의 .82 값은 최신 정답이 아니다.
- 뒤 밑단을 낮춰 측면 비율을 맞췄으며 스트랩 끝은 안으로 넣었다. 금속 버클은 외부 노출과 측면 돌출을 별도로 검사한다.
- gallery8 내부 사진은 원본 해시 `7832dd5562cf0a66ac8f0a1ca83c05f0dd63b8a2f843698fa53c089badaad7b6` 그대로 파생 public 에셋에 복사했다. 극점 부근 UV는 X/Z에 각각 arc^.65/arc^.95를 사용하고 밑단 변화율도 유지해 리벳 확대와 테이프 글자 늘어짐을 줄였다.
- 원본 갤러리9장은 모두 보존 대상이다. 착용 사진1–3은 형태 참고만 하며 사람 픽셀을 상품 표면에 쓰지 않는다.

이 반복은 네이비 단품의 검증이다. 실제 전체 매장 안정성, 선반 접촉, 다른5개 모자와 운영 반영까지 통과했다고 확대 해석하지 않는다.
