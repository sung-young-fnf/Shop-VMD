# 여러 SKU와 비니·버킷햇·선바이저

이 문서는 확장 제작 중 실제로 발견한 오류와 검증 방법을 기록한다. 특정 구현 전체가 실물 스캔 수준으로 검증되었다는 인증은 아니다.

## 자료 승인과 역할 지정

- 로컬 상품 목록의 SKU, 사진 URL의 SKU, 실제 색상을 대조한다. 다른 상품 URL이 연결된 행을 자동으로 허용하지 않는다.
- 기존 원본을 보존하고 추가 자료는 별도 디렉터리에 둔다. 원본과 배포 이미지 각각의 URL·해시·해상도·변환 이력을 남긴다.
- 갤러리 번호는 면 이름이 아니다. 모든 후보를 직접 보고 front/rear/관찰된 측면/내부/디테일을 지정한다. 정면과 평평하게 놓은 정면을 앞·뒤로 오인하지 않는다.
- 배포 파일명에 원본 갤러리 인덱스나 내용 해시를 포함한다. 앞뒤 역할만 바꾸고 기존 front.jpg를 재사용하면 지정표와 실제 파일이 달라질 수 있다.
- CDN에 PNG를 요청해도 JPEG가 반환될 수 있다. 파일 시그니처로 실제 형식을 확인한다.
- CAD JPG는 색상표나 정면 선화만 포함할 수도 있다. 실측 치수가 없는 그림을 제조 CAD 치수로 취급하지 않는다. 사진과 도면이 모두 있는 SKU를 우선하되 누락 내역을 공개한다.
- 한쪽 측면만 있을 때 반대쪽 로고를 미러링하지 않는다. 원단을 보간한 부분과 실제 관찰한 면을 별도로 기록한다. 앞뒤 사진 두 장으로 실제 360도 복원을 입증할 수 없다.

## 유형별 구조

- 야구모자: 크라운·챙·개구부·조절끈을 유지한다. 기존 한 SKU에서 검증한 틀과 새 SKU의 사진 좌표를 혼동하지 않는다.
- 고양이 귀 비니: 앞뒤 사진의 상단 윤곽을 사용한 연속 천 구조를 만든다. 야구모자 크라운에 사진을 얹지 않는다. 두께와 측면 자료가 없으면 추정 깊이라고 표시한다.
- 둥근 비니: 높이별 폭과 닫힌 정점을 확인한다. 옆면의 깊이를 0에 가깝게 줄이거나 정면 사진판 두 장으로 대체하지 않는다.
- 끈 달린 모자: 사진 전체 bounds에는 긴 끈이 포함된다. 몸통 경계를 면별로 직접 지정하고 끈 구조는 따로 만든다. 특정 사진의 bodyFraction은 다른 SKU나 다른 면에 공통 적용하지 않는다. 매장용으로 끈을 접었다면 추정한 진열 자세임을 기록한다.
- 버킷햇: 닫힌 윗판·기울어진 크라운·둘레 챙을 별도로 구성한다.
- 선바이저: 열린 상단, 앞에서 뒤로 낮아지는 밴드, 조절끈과 전방 챙을 구성한다. 후면 사진에는 멀리 보이는 앞쪽 안감까지 들어 있으므로 후면 밴드 영역만 투영한다.
- 외피의 면 순서를 검사한다. 양면 재질로 숨겨져 있던 뒤집힌 삼각형은 FrontSide 전환 후 로고가 사라지고 안감만 보이는 문제를 만든다. 안쪽 밴드는 실제 안감 구조로 만든다.

## 사진 투영의 반복 오류

- foreground bounds는 의미 영역이 아니다. 밝은 바닥 그림자·챙 아랫면·끈·버클이 포함될 수 있다. 챙 윗천 끝과 전체 사진 실루엣 끝을 분리한다.
- 후면 중심선은 크라운의 고정된 좌우 기준에서 계산한다. 비대칭 버클이 있는 마지막 이미지 행의 좌우 bounds를 기준으로 중심을 다시 계산하면 구멍 사진이 자수 위로 밀린다. 비대칭 후면 자료를 회귀 사례로 사용한다.
- 원단 crop은 한 픽셀이 아니라 셰이더가 실제로 읽는 패치 전체를 검사한다. 로고·바닥·투명 RGB가 들어가면 상단과 반대 측면에 글자나 줄무늬가 반복된다.
- 세로 방향으로도 변하는 원단 좌표를 사용한다. 둘레각만으로 원단을 읽으면 무늬가 높이 전체에 늘어난다. 여러 위상을 부드럽게 혼합하되 실제 문양의 정확성이 사라지는지 확인한다.
- 앞뒤 사진의 밝기 차이는 접합부에서 눈에 띈다. 실제 앞뒤 로고는 각각 보존하면서, 관찰되지 않은 측면의 공통 원단 영역은 같은 좌표계와 샘플로 연결할 수 있다. 이를 실제 측면 사진이라고 부르지 않는다.
- 배경 제거는 사진 경계에 한정해 검증한다. 흰 자수, 반짝이는 장식, 니트 구멍까지 일괄 삭제하는 전역 임계값은 쓰지 않는다.

## 매장과 증거

- 허용된 SKU가 진열 수보다 적으면 한 번씩 배치한 다음 반복한다. 목록 총수·승인 수·보류 이유·실제 배치 수를 구분한다.
- 모든 SKU의 앞뒤좌우 캡처를 확보한다. 대표 상품 두 개의 통과를 전체 목록의 통과로 확대하지 않는다.
- 실제 배처 전후의 정점별 위치와 각 사진/원단 속성 대응을 확인한다. 새로운 셰이더 attribute를 추가했으면 이 검사에도 포함한다.
- 실제 매장의 카메라 이동·휠·구역 선택·보행·조명·화면 크기와 실제 집기 근접 화면을 함께 검증한다. 화면 좌표 클릭이 UI 패널을 눌렀다면 사진이나 모델 오류로 오인하지 말고 캡처에서 확인한다.
- 단품의 부분 수정 중 캡처한 전체 매장 결과를 최종 증거로 쓰지 않는다. 최종 소스 해시와 전체 캡처 세트를 고정한다.
- 통합 빌드 성공, 사진 유사도, GPU 안정성은 서로 다른 판정이다. 관찰하지 않은 기기나 뒷면의 정확성을 보장하지 않는다.
