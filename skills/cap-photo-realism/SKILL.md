# 모자 전용 실사화

검증된 입체 틀과 실제 상품 사진을 분리해 제작한 뒤 결합한다. 형태는 도면과 다각도 사진을 따르고, 색·로고·원단 외관은 실제 상품 사진을 따른다. 의류용 얕은 사진 메쉬를 모자에 그대로 적용하지 않는다.

## 적용 범위와 입력

- 기본 대상은 곡선 챙 야구모자다. 버킷햇·평챙·메시캡은 구조를 다시 분석한다. 여러 SKU를 진열하거나 비니·선바이저를 추가할 때는 [헤드웨어 확장](references/headwear-assortments.md)을 읽는다.
- 사람 없는 동일 SKU/색상의 정면·후면·측면과 원단 디테일 사진을 확보한다. 누락된 면은 추정으로 표시한다.
- 도면의 패널 수, 챙 곡률, 봉제 줄 수, 후면 구멍, 스트랩·버클을 기록한다.
- 파일 확장자로 자료 종류를 단정하지 않는다. 기존 caps 폴더의 JPG=도면, PNG=사진 구분은 해당 폴더의 관례다.
- 도면과 사진의 팀·색상이 다르면 공통 구조만 도면에서 가져오고 실제 로고·색은 해당 SKU 사진으로 결정한다.
- 원본은 보존한다. 파생 이미지에는 원본 경로·해상도·해시·crop 좌표·전처리 내용을 남긴다. 같은 파일명이라도 배포본이 잘렸을 수 있다.

## 1. 틀부터 확정하기

좌표는 +Y 위, +Z 정면/챙, -Z 후면으로 고정한다. 크라운·챙·후면 개구부·스트랩·안쪽 밴드를 별도 구조로 만든다. 이전 단일 시점에서 통과한 틀도 새 원본 다각도 사진과 다르면 수정한다. 실제 원본이 과거 수식이나 통과 판정보다 우선한다.

아래는 검증 사례의 정규화된 출발식이다. 모든 SKU의 실측 치수가 아니며 도면 비율과 다각도 비교로 조정한다. theta는 둘레각, t는 정점 0부터 하단 pi/2까지다.

```text
rx = sin(t)^0.65
backWeight = smoothstep(-cos(theta), 0, .75)
backVolume = sin(t)^.55 - sin(t)^.95 + .22*sin(t)^4*sin(2*t) - .03*sin(t)^8
rz = sin(t)^.95 + backWeight*backVolume
x = sin(theta) * rx * (1 - inset)
z = cos(theta) * rz * (1.05 - inset)
a0 = sqrt(1-.91^2)
frontRise = max(0,(cos(theta)-a0)/(1-a0))
base = .02 + (.10*cos(theta)+.14*frontRise^2-.13*(1-cos(theta)))*sin(t)^2
y = base + 1.18*max(0,cos(t))^1.05
```

- 정점에서는 둘레별 base 보정이 사라져야 한다. 분수 지수에 들어갈 cos 값은 음수가 되지 않게 제한한다.
- 둥근 모자가 각지거나 정면 어깨가 좁으면 X/Z 단면을 따로 검토한다. 이 사례는 X의 sin^.65로 정면 폭을 확보하고 Z의 sin^.95로 측면 둥글기를 유지했다. 모든 축의 지수를 함께 바꾸면 한 면을 고치며 다른 면을 망칠 수 있다. 밑단의 옆면~뒤쪽은 직선 기울기, 앞 중심은 별도 상승 곡선으로 분리한다. 사진 원근 때문에 직선 밑단도 화면에서는 휘어 보일 수 있다.
- 후면 개구부는 사진의 흰색 부분이 아니라 실제 하단 메쉬 경계로 만든다.
- 뒤통수는 정면의 둥글기와 별도로 본다. `sin(t)^p`만 쓰면 반경이 밑단까지 커져 뒤쪽이 뾰족한 쐐기처럼 끝날 수 있다. 원본에서 뒤통수 최대 돌출 높이와 밑단의 안쪽 복귀량을 확인한다. 낮은 끝만 깎지 말고 위·중간 어깨의 볼륨도 비교한다. 위 식은 앞 반구를 고정하면서 뒤쪽에만 넓은 볼륨과 작은 밑단 말림을 더한 특정 SKU 사례다.

```text
opening = cos(theta)<0 and abs(sin(theta))<.46
  ? .58*sqrt(1-(sin(theta)/.46)^2) : 0
lowerAngle = acos((opening/1.18)^(1/1.05))
```

챙은 u=-1..1(좌우), q=0..1(크라운 접합부부터 앞끝)로 만든다. 부착 범위를 크라운의 전방 반구 전체로 잡으면 챙이 옆면 뒤까지 감싸는 날개가 생긴다. 부착 폭을 줄인 만큼 전체 챙 폭까지 줄이면 정면이 좁은 혀 모양이 된다. 측면의 부착 끝점과 정면의 앞끝 폭을 독립적으로 맞춘다. 아래 k=.91은 네이비 NY 다각도 보정값이며 공통 치수가 아니다.

```text
k = .91
s = k*u
a = sqrt(max(0,1-u*u))
root = crown(theta=asin(s), t=pi/2)
x = s+.30*u*q*a
y = root.y-(.32+.30*s*s)*q*a+.025*q*q*a-.48*u*u*q*a
z = root.z+.86*a*q
```

q=0의 챙과 theta=asin(k*u), t=pi/2의 크라운 경계를 비교해 접합을 검증한다. 부착각은 줄이되 양 끝의 연장량은 0으로 수렴시켜 별도 옆 날개가 생기지 않게 한다. 챙 아랫면에는 얇은 두께를 준다. 정면 한 장만 맞추지 말고 측면·후면·아래쪽에서 구멍과 관통을 검사한다. 과거 단품 검증은 새 원본 사진의 형상 지적보다 우선하지 않는다.

챙 각도와 좌우 곡률은 별도 변수다. 앞코를 더 숙이라는 요청에는 root 대비 tip의 낙차를 바꾸고 길이·접합은 보존한다. 크라운을 수정하면 안감·밑단 테두리·패널 봉제·후면 구멍도 같은 곡면식을 따라야 한다. 사진 투영용 기준 좌표를 새 형상 좌표로 무조건 덮어쓰지는 않는다.

### 다각도 보정 순서

1. 정면·측면·후면·사선의 카메라 고도, 방위각, FOV, 거리와 target을 기록하고 원본과 맞춘 뒤 고정한다. 내려다본 화면의 짧아진 챙을 형상 오류로 단정하지 않는다.
2. 크라운 폭으로 정규화한 전체 높이, 로고 크기·위치, 챙 중앙과 양 끝 높이, 부착점, 뒤 밑단을 비교한다. 사진 한 장의 숫자를 제조 치수라고 부르지 않는다.
3. 앞뒤 기울기, 좌우 말림, 부착 폭, 앞끝 폭을 각각 수정한다. 카메라를 바꾼 뒤에는 기존 로고 위치 보정을 재검토한다.
4. 후면 구멍의 검은 띠는 안감인지 실제 앞쪽 챙이 가린 것인지 raycast 등으로 확인한다. 정당한 메쉬를 숨기거나 흰 면으로 덮지 않는다.
5. 조절끈 끝은 뒤 밑단 안에 들어가되 금속 버클은 원본처럼 외부에 보여야 한다. 끈·버클을 한꺼번에 안으로 옮기면 부품이 사라질 수 있으므로 후면과 측면을 함께 확인한다.
6. 전체 폭·높이만 맞았다고 측면을 통과시키지 않는다. 크라운 높이별 뒤 윤곽을 여러 행에서 비교한다. 카메라와 기준점 정렬의 불확실성을 기록하고, 원본 PNG의 투명 RGB는 윤곽 측정에서 제외한다. 뒤 밑단을 말아 넣으면 조절끈도 새 밑단 깊이를 따라야 하며, 고정된 옛 좌표를 쓰면 천 끝이 다시 튀어나온다.

## 2. 실제 사진을 표면에 투영하기

사진 외관 보존 모드의 기본은 sRGB 사진 텍스처와 `MeshBasicMaterial`, `toneMapped: false`다. 사진에 이미 찍힌 원단·자수·음영을 보존한다. 이것은 조명 제거된 albedo나 물리 기반 원단 복원이 아니다. 야간 조명에서도 밝게 보일 수 있으므로 실제 매장 조명에서 별도로 판단한다.

- 정면은 실제 로고와 앞 패널, 후면은 뒤 자수와 스트랩, 측면은 옆 패널, 디테일 컷은 로고 없는 원단 영역에 사용한다.
- 기본 map뿐 아니라 shader uniform으로 참조한 사진도 로딩 완료 조건에 포함한다.
- 사진 투영 좌표와 렌더링 메쉬 좌표를 분리한다. `capSourcePosition` 같은 기준 속성을 메쉬에 보관하고, 집기 배치·회전·병합 후에도 보존한다.
- 사진 픽셀 좌표를 UV로 변환할 때 이미지 크기와 Y 방향을 명시한다. 좌우 반전은 글자와 후면 사진 방향을 기준으로 검증한다.
- 정면/후면/측면/상단의 영역 가중치를 부드럽게 혼합한다. 정규화 위치 기반 혼합을 실제 표면 normal 기반 투영이나 물리적 복원이라고 부르지 않는다.
- 측면 PNG의 투명 부분은 유효한 다른 사진/원단색으로 채운다. 투명 RGB를 그대로 혼합해 검은 테두리를 만들지 않는다.
- 상단 원단은 로고 없는 crop을 사용한다. 반복 격자가 보이면 여러 위상의 겹침 혼합을 시도하고 확대·축소에서 이음선과 모아레를 확인한다. 이것만으로 완전한 seamless를 보장하지 않는다.
- 후면 사진의 개구부 위치가 틀과 다르면 사진 좌표를 재매핑한다. 메쉬에 추가 구멍을 뚫어 사진 배경을 따라가지 않는다.
- 어두운 원단의 밝은 배경 제거 임계값을 흰 모자나 흰 자수에 복사하지 않는다. SKU별 영역·색 공간·alpha를 검사한다.
- 실제 내부 사진이 있으면 테이프·직조 라벨·금속 리벳을 그 사진에서 가져온다. 곡면의 극점 근처에서 선형 UV는 작은 리벳을 거대하게 확대할 수 있다. 곡면 반경 변화율에 맞춘 매핑과 밑단에서 0이 아닌 변화율을 사용하고, 원본 대비 리벳 직경과 글자 종횡비를 검사한다. 검은 구멍을 큰 사진 원판으로 덮어 해결하지 않는다.

## 3. 디테일은 한 번만 표현하기

각 디테일에 사진 또는 모델 중 표현 책임자를 하나 정한다.

| 디테일 | 원칙 |
|---|---|
| 통기구 | 사진에 선명한 통기구가 있으면 모델 링을 겹쳐 두 배로 만들지 않는다. |
| 버클 | 곡면 메쉬에 실제 버클 사진을 투영할 수 있다. 크라운 사진의 중복 버클은 원단으로 대체하며, 새 각인 문구를 만들지 않는다. |
| 로고·문구 | 실제 사진을 보존한다. 글자 재생성이나 임의 폰트로 대체하지 않는다. |
| 봉제선 | 사진의 봉제선과 중복되지 않게 얇게 표현하고 자수를 가로지르지 않는다. |
| 내부 테이프 | 관찰되지 않은 상표·문구를 만들지 않는다. 추정한 내부는 무지로 표시한다. |

별도 로고 패치가 필요하면 크라운 곡면을 따라 충분히 분할한다. 작은 lift만으로 관통이 해결된다고 가정하지 않는다. 큰 삼각형이나 단일 triangle fan은 면 중앙이 크라운 안으로 파고들어 자수가 잘릴 수 있으므로 면 내부의 간격도 검사한다.

## 4. 매장 배치 및 자원 관리

- 고정된 Y 값으로 factory 위치를 덮어쓰지 않는다. 회전·균일 축척을 적용한 실제 모자 bounds의 최저점을 실제 선반 상단에 맞춘다. 모자와 지지면은 같은 좌표계에서 비교하며, 접촉 여유는 장면 단위로 선언한다(검증 사례: 1mm). 접힌 옷 위에서는 옛 두께 상수가 아니라 해당 옷 geometry의 최대 Y를 사용한다.
- 모자 자체뿐 아니라 모든 부모의 축척도 검사한다. 집기 부모의 비균일 축척은 크라운과 챙을 눌러 버린다. 의류 등 기존 배치를 보존하면서 모자를 비왜곡 부모로 분리하고, 공간에 맞출 때는 세 축에 같은 배율만 적용한다. 회전된 부모 밑에서 축별 역배율만 주는 방식은 shear까지 해결한다고 가정하지 않는다.
- 최저점만 맞추지 말고 전체 깊이·폭과 선반 경계, 쇼케이스 뚜껑·칸막이·앞뒤 유리의 간섭도 확인한다. 한 대표 모자의 통과를 전체 진열의 통과로 대체하지 않는다.
- 단품 고해상도와 매장 반복 진열의 예산을 분리한다. 실제 진열 수로 draw calls·삼각형·텍스처 크기·프레임 시간을 측정한다.
- 같은 SKU의 geometry/material/texture는 가능한 범위에서 공유한다. 한 인스턴스를 제거하면서 공유 자원을 dispose하지 않는다.
- 병합 대상의 attribute 구성을 맞춘다. 무텍스처 메쉬의 불필요 UV는 제거할 수 있지만 사진 투영용 속성을 삭제해 오류를 숨기지 않는다.
- 실제 배처 전후에 같은 재질의 정점별 XYZ와 사진 기준 속성의 대응을 검사한다. 좌표를 축 구분 없이 정렬한 숫자 집합은 잘못된 변환도 통과시킨다. Float32 오차 허용치를 명시하고 정점 순서가 바뀌는 배처라면 명시적인 정점 대응을 구축한다.
- 전체 매장과 실제 배칭된 집기의 근접 화면을 둘 다 남긴다. 앞 상품·유리·집기가 가린 것과 모자 형상 왜곡을 구분하고, 검사 통과를 위해 주변 구조를 숨기지 않는다. 진열용 검사 조명과 전체 매장 조명을 혼동하지 않는다.
- 사용자 운영본과 개발본을 분리하고 승인 없이 운영에 반영하지 않는다.
- WebGL context loss는 시각 품질과 별도의 실패다. 오류 화면을 숨기거나 이벤트를 무시해서 성공 처리하지 않는다. GPU 원인은 증거 없이 단정하지 않는다.

## 5. 완료 판정

두 게이트를 따로 기록한다. A만 통과한 경우 매장 적용 완료라고 보고하지 않는다.

### A. 모자 단품

- 정면·양 측면·후면·상단·하단·사선에서 실제 사진과 비교한다.
- 로고 방향·크기·색, 크라운 비율, 챙 접합, 개구부, 스트랩, 중복 디테일을 확인한다.
- 드래그·휠 확대/축소·새로고침 후 같은 결과이며 텍스처 누락·shader 오류가 없어야 한다.
- 원본 사진 변경이 없고 실제 로드된 빌드/소스에 증거가 연결되어야 한다.

### B. 실제 매장

- 실제 진열 수와 배치 변환을 사용해 같은 모자의 외관이 유지되는지 확인한다.
- 확대/축소·회전·보행·구역 전환·조명 전환·다른 화면 크기를 검사한다.
- context loss/restored가 한 번이라도 발생하면 안정성 실패로 기록한다. 복구 뒤 캡처가 나온 것만으로 통과시키지 않는다.
- 품질 한계와 관찰하지 못한 영역, 실행 환경, 오류 로그, 빌드 식별자, 캡처를 남긴다.
