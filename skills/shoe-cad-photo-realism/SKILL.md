# CAD와 실제 사진으로 만드는 Three.js 신발

목표는 CAD의 설계 정보를 체계화하고 **동일 제품의 실제 다각도 사진**으로 외관과 소재를 재현하는 것이다. 한 장의 사진을 모든 면에 늘려 붙이거나, 보이지 않는 면을 근거 없이 만들어 완성으로 취급하지 않는다. 이 스킬은 독립적으로 사용할 수 있으며 기존 shoe_photo_realism 절차의 CAD 확장판이다.

## 1. 필수 선행 단계: 사진 한 장에서 다각도 자료 찾기

**사용자가 사진 한 장만 제공하는 상황을 기본 입력으로 취급한다. 모델링·면별 형상 제작을 시작하기 전에 동일 제품의 다른 각도 사진을 먼저 찾아야 한다.** 사진이 이미 여러 장이어도 아래 목록의 누락 여부부터 조사한다.

1. 입력 원본과 CAD를 직접 열어 브랜드, 상품명, 스타일/SKU, 색상 코드, 로고·팀, 소재, 밑창 특징을 확인한다. 파일명만으로 동일 제품이라고 단정하지 않는다.
2. 사용자 지정 폴더와 주변의 reference/shoes, shoes-detail, cad 등 실제 자료 위치를 검색한다. 기존 출처 목록·상품 URL이 있으면 재사용한다.
3. 로컬에 필요한 사진이 없으면 웹에서 **정확한 SKU와 색상 코드**로 검색한다. 공식 상품 상세·공식 이미지 갤러리를 우선하고, 필요한 경우 동일 제품을 확인할 수 있는 판매처 자료까지 확인한다. 작은 검색 썸네일에서 멈추지 말고 가능한 원본 크기 이미지를 확보한다.
4. 다음 각도를 각각 찾아 사진 목록을 채운다. 한 장이 여러 부위를 보여도 정면·측면·사선의 차이를 기록한다.

| 확보 대상 | 확인할 정보 |
|---|---|
| 위쪽 | 앞코 평면 윤곽, 혀, 끈 교차와 구멍, 중앙 고리, 입구 |
| 바깥쪽 측면 | 로고, 외측 패널, 봉제선, 갑피·고무 경계 |
| 안쪽 측면 | 내측 비대칭, 로고 유무, 내측 절개 |
| 앞쪽 | 앞코 폭·두께, 범퍼, 앞끝 들림 |
| 뒤쪽 | 뒤축 탭·문구, 중앙 봉제, 패딩과 고무 감싸기 |
| 아래쪽·밑창 | 트레드 배열·홈·로고, 외곽과 앞뒤 형상 |
| 앞 사선·뒤 사선 | 사진 간 접합 관계, 깊이와 곡률, 가려진 경계 |
| 소재 확대·내부 | 직조·스웨이드·자수·끈 결, 안감과 깔창 표기 |

5. 후보 사진을 직접 열고 **스타일뿐 아니라 색상·로고·패널·밑창까지** 일치하는지 확인한다. 같은 스타일의 다른 색상은 보조 구조 자료로 표시하며 해당 색상·로고를 본 제품에 옮기지 않는다. 같은 사진의 확대본·잘라낸 이미지·좌우 반전은 새로운 시점이 아니다.
6. 원본 크기, URL/로컬 경로, SHA256, 각도, 관찰 부위, 가림, 동일 제품 판단 근거를 `source-manifest.json`에 기록한다. 전체 연락판과 `view-coverage.md`를 만들어 확보·부분 확보·미확보를 구분한다.

**사진 확보 게이트:** 필요한 면을 찾기 위한 로컬·웹 탐색과 동일 제품 검증을 마치기 전에는 제작을 시작하지 않는다. 탐색해도 필요한 면이 없거나 제품 식별이 불확실하면 그 상태를 숨기지 않는다. 추가 식별 정보·사진을 요청하거나, 미확보 면을 명시한 추정 제작을 허용할지 확인한다. 답변을 기다리는 동안 CAD 분석과 확보 사진의 선 추적은 진행할 수 있지만 미확보 면의 모델링은 진행하지 않는다. 생성 이미지나 업스케일로 새 시점을 만들어 실제 사진을 확보했다고 보고하지 않는다.

웹·파일 접근 도구가 없으면 검색을 수행했다고 주장하지 말고 정확한 접근 한계를 밝힌다. 예전에 승인받은 범위나 같은 제품의 검증된 자료가 있으면 중복 요청하지 않는다.

## 2. CAD 분석과 근거 우선순위

사진 확보 작업과 병행해 [CAD 분석 계약](references/cad-contract.md)을 읽고 다음을 구조화한다.

- 제품 식별·색상·시즌·샘플 사이즈·라스트/아웃솔 번호.
- 소재명, 적용 영역, 색상, 두께, 표기 치수와 리더선 끝점.
- 실제 봉제선, 소재 경계, 실루엣, 가림, 장식/인쇄를 구분한 윤곽.
- 깔창과 밑창 도식의 종류, 기준 방향, 축척 유무, 비대칭과 허리 폭.
- 원본 좌표·읽기 확신도·불분명한 숫자·사진과 충돌하는 사양.

CAD가 제조용 치수 도면인지 단일 래스터 사양서인지 구분한다. 샘플 사이즈를 밑창 실측 길이로 사용하지 않는다. 작은 깔창 윤곽은 내부 바닥의 평면 형태를 안내하지만 외부 트레드나 숨은 내부 두께를 결정하지 않는다.

기본 목표가 실제 상품 재현이면 **같은 색상의 생산 사진이 보이는 외관을 결정**하고 CAD는 소재 사양과 설계 의도를 제공한다. 사용자가 CAD 설계안 자체를 요청하면 그 목표를 따른다. 충돌은 기록하고 묵시적으로 섞지 않는다.

## 3. 해상도와 소재 준비

원본을 먼저 확대해서 판단한다. 작은 화면 표시와 저해상도 원본은 다르다. 원본 매크로·더 큰 동일 제품 이미지를 찾은 다음 실제 부족한 영역만 업스케일한다. 생성형 처리는 지원되는 이미지 도구로 별도 파일에 수행하고 생성된 실밥·글자·섬유를 관찰 근거로 사용하지 않는다.

원본은 보존하고 파생 크롭마다 원본 해시, 원본 픽셀 사각형, 리사이즈·색 보정·혼합 내역을 기록한다. 알파 밖의 RGB, 제품 그림자, 겹친 다른 신발을 소재에 포함하지 않는다. 로고·자수·문구·봉제는 실제 해당 픽셀을 보존한다.

필요 도구: 이미지 열람·크롭, 로컬/웹 검색, Three.js와 대상 프로젝트 빌드 도구, 실제 브라우저 조작·캡처. 기존 스택과 잠금 파일을 우선한다. 특정 이미지 생성 도구나 하네스가 요청됐으면 실제 사용 가능한 절차만 수행하고 미실행 게이트를 통과했다고 주장하지 않는다.

## 4. 좌표·공통 경계와 면별 위임

사진 확보 게이트를 통과한 후 라스트, 정규화 단위, 좌표축, 사진별 등록 변환을 정한다. 원본 픽셀·분석본 픽셀·형상 좌표·source UV를 분리해 기록한다. 형상을 보정하더라도 원본 윤곽과 source UV는 유지한다.

한 물리적 경계에는 한 경계 데이터와 한 형상 함수가 있어야 한다. 이웃은 실제 같은 꼭짓점/샘플을 사용하고 자신의 사진 UV를 갖는다. 좌우 사진의 높이 기준 차이를 한쪽 아이스테이만 눌러 해결하지 않는다.

면별 위임 요청 시 감독이 아래 책임을 나누고 통합 승인까지 맡는다. 범위가 작거나 위임이 불가능하면 같은 책임 구분으로 순차 수행하고 실제 위임 여부를 정확히 알린다.

| 책임 | 소유 영역과 전달물 |
|---|---|
| 사진·CAD 분석 | 사진 확보 목록, CAD JSON, 출처·좌표·충돌표 |
| 공통 프레임 | 라스트, 좌표/등록, 공통 경계, 조립 코드 |
| 바깥면 | 외측 절개·로고·봉제, 앞코/뒤축/고무 접합 |
| 안쪽면 | 내측 비대칭과 윤곽, 공통 경계 |
| 윗면 | 혀·아이스테이·구멍·끈·중앙 고리·깔창 |
| 앞코 | 앞코 캡과 상단 삽입부, 범퍼 연결 |
| 뒤축 | 탭·뒤축·입구 패딩·곡면 안감 |
| 밑창 | 측벽·앞뒤 감싸기·트레드·홈 |
| 검수 | 실제 브라우저 증거, 기능/소스와 원본 외관 대조 |

각 작업 지시에 **소유 파일, 입력 사진과 영역, 공유 경계, 변경 제한, 국소 비교 캡처·접합 검사**를 포함한다. 공동 작업 중임을 알리고 다른 작업을 되돌리지 않게 한다. 공통 경계 수정은 한 담당자가 조정하고 영향받는 모든 면에 알린다. 담당자의 완료 보고만으로 승인하지 않고 감독이 원본과 통합 결과를 직접 본다.

## 5. 곡면 형상과 사진 재질

세부 제작·결함 진단 시 [재구성 주의점](references/reconstruction-notes.md)을 읽는다.

- 사진 윤곽을 삼각분할·세분해 실제 라스트 곡면에 올린다. 평면 사진 카드로 깊이를 대체하지 않는다.
- 소재 경계와 봉제선을 먼저 구분한 후 면을 만든다. 사선에서 중복 면·틈·가림을 검증한다.
- 끈은 원본의 **구멍 간 연결 그래프와 교차 순서**를 먼저 기록한다. 일반적인 U줄이나 X줄을 가정하지 않는다. 끝점뿐 아니라 곡선 내부 제어점도 해당 연결에 맞춘다.
- 패딩은 안쪽으로 말리는 부피와 연속 안감을 갖는다. 접합 위치·법선·조직 크기·UV 위상을 함께 맞춘다.
- 깔창 윤곽은 내부 라스트에 맞추고 인솔을 독립적으로 볼 수 있게 한다. 보이지 않는 깊이·아치·두께는 추정으로 기록한다.
- 사진 외관 모드는 sRGB 컬러와 적절한 색 관리로 시작한다. 부피가 필요한 끈/안감 등에는 조명을 선택적으로 유지할 수 있다. 촬영 명암이 남음을 명시하고 근거 없는 sheen을 추가하지 않는다.
- normal/roughness/AO는 검증된 해당 자료가 있을 때 사용한다. 컬러 사진 밝기를 측정 물성으로 간주하지 않는다. UV 채널과 색 공간은 설치된 Three.js 버전을 확인한다.

## 6. 감독의 수정 루프와 완료 기준

원본의 같은 부위를 지정해 **관찰 → 원인 확인 → 해당 담당자 수정 → 동일 시점 재촬영**한다. 수치 통과는 외형 통과가 아니다. 반대로 카메라·조명 차이만으로 이미 해결된 부분을 다시 설계하지 않는다. 실제 근거가 더 이상 없으면 남은 불확실성을 밝히고 임의 수치 조절을 반복하지 않는다.

완료 전 다음을 현재 결과에서 확인한다.

- 확보한 모든 사진과 위·양쪽·앞·뒤·아래·사선·소재 확대 뷰를 대조한다. 없는 사진과 추정 면을 명확히 표시한다.
- 끈 단면/방향/끝점, 고리의 부착·통과 관계, 혀 하단, 갑피/고무, 뒤축/측면, 패딩/안감, 깔창 간섭을 검사한다.
- 실제 웹에서 회전·드래그·줌·초기화·원본 선택·CAD 표시·분리/진단 모드를 실행한다. 제공한 기능과 화면 너비에 맞춰 전체 상태 목록을 만든다.
- 실제 사용되는 텍스처를 모두 검사한다. 일반 map뿐 아니라 컴파일된 shader uniform의 텍스처도 포함한다.
- 마지막 변경 후 캡처하고 소스/에셋 전후 해시, 이미지 해시·크기, 로딩/런타임 오류를 기록한다. 수정 전 캡처를 최신 통과 근거로 재사용하지 않는다.
- 해당 환경의 독립 QA 지침을 따른다. 승인 결과는 같은 현재 소스와 완전한 캡처 목록에 연결한다. 모바일·태블릿 CAD 항목의 짧은 부정어/어미가 혼자 줄바꿈되지 않는지도 본다.

체크·사진·메시·에이전트 수와 포트는 제품/화면에 맞게 정한다. 과거 사례 수치를 의무값으로 복사하지 않는다. 결과가 사진 기반인지 CAD 설계안인지, 실측/추정 범위를 구분해 전달한다.

## 7. 산출물과 재사용

필수 결과는 출처/시점 확보 목록, CAD 분석 JSON·설명·충돌표, 원본/파생 이미지, 면별 생성 코드·공통 경계, 웹 뷰어, 현재 검수와 인계 기록이다. 코드 재사용 시 조립 진입점·공유 모듈·각 면·재질·에셋·의존성을 함께 옮기고 대상 경로에서 다시 검증한다.

사용자 지정 경로와 개발/운영 경계를 우선한다. 새 서버는 리스너 확인 후 실행하고 기존 서버를 자동 종료하지 않는다. 단품 제작 완료가 운영 배포나 다른 앱 통합 승인은 아니다. 작업 후 소유한 진단 브라우저를 닫고 위임 기록을 보존한다.

이번 사례의 구현 위치와 근거가 필요할 때만 [검증 사례](references/verified-case.md)를 읽는다. 스킬 사용 자체에는 그 로컬 프로젝트가 필요하지 않다.

사용 예시: “$shoe-cad-photo-realism 이 사진 한 장과 CAD로 같은 신발을 만들어줘. 먼저 동일 색상의 위·아래·양쪽·앞뒤·사선 사진을 찾아 목록을 확정하고, 면별 위임으로 제작한 뒤 웹에서 보여줘.”
