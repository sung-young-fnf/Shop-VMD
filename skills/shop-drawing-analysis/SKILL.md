# 매장 도면 분석과 제작 위임

도면을 공간·집기·재료 사양과 원본 근거 이미지로 변환한다. 매장 고유 치수·브랜드·집기 수량은 해당 프로젝트에 두고 이 스킬에 고정하지 않는다.

## 전체를 먼저 파악

- PDF 읽기 스킬이 있으면 사용한다. 페이지 수·원본 파일 해시·페이지 크기·회전·도면 제목과 PDF 페이지 번호를 기록한다. 반복되는 표제란 도면번호는 고유 키가 아니다.
- 텍스트 추출과 전체 페이지 렌더링을 함께 수행한다. 썸네일 묶음으로 전체를 훑은 뒤 평면·주요 입면을 크게 확인한다. 치수는 추출 문자열만으로 해석하지 않는다.
- 표지·마감표·최종 평면·철거·가설·설비·상세·사진 페이지를 구분한다. 파일명 날짜를 모든 시트의 최종 개정일로 간주하지 않는다.
- 팀 요청이 있을 때 총괄이 실제 도면 구성으로 먼저 분할한다. 외관, 공간/입면, 재료/설비, 집기군, 부속 공간처럼 명확한 범위와 산출물 소유권을 부여한다. 공유 평면은 함께 읽되 편집 파일은 겹치지 않게 한다. 페이지 전수 목록으로 누락과 이중 소유를 확인한다.

## 공간과 부품의 해석

- 정문·주요 벽·기둥·코어·창고·피팅룸·카운터를 평면에서 연결한다. 방향 표시가 없으면 도면 상하좌우를 사용하고, 입면을 볼 때 좌우 반전을 확인한다.
- 면적표의 판매/피팅/코어/총합을 구분한다. 부분 도장 면적이나 자재 로스 포함 발주 면적을 매장 전체 면적으로 대체하지 않는다.
- 치수 단위와 기준점을 보존한다. 외곽/유효폭, 문짝/문틀, 본체/가드, 전체 높이/설치 이격은 서로 다른 수치다. 축이 불명확하면 `W×D×H`로 억지 정규화하지 않는다.
- 집기 완제품, 내장 부품, 좌우 대칭형, 폭별 변형, 반복 상세 페이지를 분리한다. 상세도 수량과 평면 설치 수량을 서로 다른 필드로 둔다. 하부장·조명·백판을 완제품 개수에 다시 더하지 않는다.
- 도면 색칠은 마감색이 아닐 수 있다. 마감 코드·문자 주석·재료표를 대조한다. 동일 재료 코드가 서로 다른 재질에 쓰이면 원문과 위치를 보존하고 내부 식별자만 분리한다.
- 조명은 기구별 색온도·설치 높이·방향·범례 수량을 기록한다. 공간 전체에 단일 색온도를 강제하지 않는다. 천장/보/레이스웨이 높이는 교차 시 배치 확인이 필요하다.
- 기존 존치, 철거, 신설, 공사 가림막, 단기 이벤트를 최종 매장 상태와 구별한다. 도면에 없는 상층 판매 공간이나 상품 SKU를 꾸며 넣지 않는다.

## 원본 캡처를 위임 자료로 남기기

프로젝트의 `reference/drawing_captures/` 같은 명시적 하위 폴더에 저장한다. 원본 PDF와 사용자 이미지를 변경하지 않는다.

- `pages/page-NNN.png`: 전체 페이지. PDF 기준 1부터 시작하며 여백/표제란도 보존한다.
- 구역별 폴더의 `pNNN_<component>_<view>.png`: 치수선·마감 주석·접합 관계까지 포함한 확대 영역. 전체 페이지 이미지를 확대 복사하지 말고 PDF 원본에서 높은 해상도로 렌더링한다.
- `manifest.json`: 원본 PDF 식별자/해시, PDF 페이지, 이미지 상대 경로, PDF 좌상단 좌표 기준 크롭 사각형, 렌더 배율, 부품 코드, 용도를 보존한다. 전체 페이지 목록과 담당별 상세 목록을 분리할 수 있다.
- `README.md` 또는 위임 색인: 공간/부품 → 보고서 → 전체 페이지 → 확대 캡처를 연결한다. 추출 텍스트는 검색 보조 자료로만 사용한다.

캡처 결과를 실제 열어 확인한다. 치수가 잘렸거나 글씨가 읽히지 않으면 크롭 범위/렌더 해상도를 바꾼다. 전체 페이지와 확대 이미지를 함께 전달해야 후속 에이전트가 맥락을 잃지 않는다. 원본 내 연락처 등은 캡처에 남아 있을 수 있으므로 외부 공개 전에 별도 비식별 처리를 요구하고, 분석 본문에는 불필요한 개인정보를 전재하지 않는다.

## 명세와 확인 대기 항목

각 공간은 위치, 역할, 필수 구현 부품, 치수·마감, 관련 집기 코드, 페이지/캡처 링크, 미확인 사항을 갖는다. 각 중요 수치에는 근거 페이지를 붙인다.

서로 다른 치수를 발견하면 값을 평균하거나 상세도를 자동 우선하지 않는다. 양쪽 페이지·치수 기준·잠정 제작 가정·가정 변경 영향을 기록한다. 명시 사실 / 시각 관찰 / 추론 / 구현 제안을 구별한다.

후속 제작 위임은 담당 오브젝트 계층, 입력 파일 목록, 좌표·단위 계약, 선행 의존성, 허용 단순화, 수량 검증, 미확정 선택지를 포함한다. 확정되지 않은 전체 스케일·배치 기준은 고정밀 제작 전에 해결한다. 구현 권한이 없는 분석 요청에서는 명세와 확인 항목에서 끝낸다.

## 완료 기준

- 원본 전체 페이지가 색인과 담당 확인표에 포함된다.
- 중요 공간과 부품에 페이지 근거와 열리는 캡처 링크가 있다.
- 캡처 이미지가 디코딩되고 해상도·크롭 메타데이터가 일치한다.
- 수량·치수·마감 충돌과 원본에서 알 수 없는 범위를 숨기지 않는다.
- 총괄 요약만으로 매장 구성과 제작 순서를 이해할 수 있고, 상세 보고서로 부품까지 내려갈 수 있다.
- 이후 구현을 요청받으면 프로젝트의 Three.js/하네스 스킬로 연결한다. 분석 패키지가 있다는 이유만으로 모델 QA나 하네스 통과를 주장하지 않는다.
