# 매장 Three.js · VMD 공용 스킬

매장 자료를 근거로 편집 가능한 3D 공간과 실제 탐색 웹 페이지를 만든다. 도면, 공간 모델, 집기·상품 배치, 카메라, UI, 검증 증거를 분리한다. 이 문서가 있는 디렉터리를 `SKILL_DIR`, 구현 대상 프로젝트 루트를 `WORKSPACE`로 해석한다. 개인 PC 경로나 고정 포트는 사용하지 않는다.

## 필요한 자료와 범위 결정

- 도면, 매장 외관·실내 사진, 집기 상세, VMD 배치안 중 제공된 자료를 먼저 전부 확인한다.
- 사용자 목표가 외관 쇼케이스, 실내 탐색, 배치 검토, 편집기 중 무엇인지 기존 요청에서 결정한다. 보기만 요청했는데 집기 편집·저장·외부 시스템 연동까지 추가하지 않는다.
- 자료가 불완전해도 구현 가능한 범위는 진행한다. 미확인 치수와 상품 수량을 실제 값으로 단정하지 않고 사양에 `inferred` 또는 `unknown`으로 남긴다.
- 빈 매장·쇼핑몰 내부 점포에는 외부 지붕이나 정원, 굴뚝을 기본 구성으로 넣지 않는다. 이번 주택의 형태나 녹색 팔레트를 모든 매장의 기본값으로 삼지 않는다.

## 구현 순서와 산출물

1. **근거 정리**: 파일별 원본 크기·역할·해시·관찰 내용을 source manifest로 작성한다. 도면 축과 출입구 방향, 치수 보정 기준을 정한다.
2. **사양 작성**: `store-spec.json`에 좌표 변환, 공간 경계, 존, 개구부, 집기, 상품 배치, 재질, 카메라, 품질 기준을 둔다. 필요한 필드만 만들고 미지원 기능을 완료 표시하지 않는다.
3. **기본 구조**: 외곽, 바닥, 벽, 기둥, 출입구, 쇼윈도와 주요 집기를 만든다. 위·전면·후면·양 측면 또는 실내 대응 시점에서 실제 배치를 확인한 뒤 디테일을 추가한다.
4. **집기·진열·재질**: 제공 자료의 선반 단수, 행거 높이, 진열대 크기, 상품 배치 밀도와 재료를 재구성한다. 스타일화 수준과 추정 사항을 공개한다.
5. **탐색 경험**: 요청된 전체·실내·평면 보기와 존/집기 선택을 연결한다. 천장·전면벽 절개는 실제 내부를 보여야 한다. 선택 상태와 초기화 경로를 DOM UI로 제공한다.
6. **검증과 수정**: 모든 선택 대상의 실제 가시성, 모바일 UI, 키보드, 조명, 리셋, 런타임 오류와 성능을 확인한다. 소스 변경 후 영향받는 증거를 새로 캡처한다.

권장 모델 인터페이스는 `createStoreModel(spec)`에서 독립된 `root`, `zones`, `fixtures`, `selectables` 및 필요한 보기 제어를 반환하는 형태다. 이름은 기존 코드의 규칙에 맞춘다. JSON 입력은 경계에서 검사하고, 내부 모델은 명시적인 타입을 사용한다.

## 매장 사양의 의미

- `zones`: 입구, 쇼윈도, 주력 상품, 판매, 피팅, 계산, 창고 등 실제 자료에 있는 공간. `zoneId`는 UI·3D·QA에서 동일하다.
- `fixtures`: 행거, 선반, 테이블, 마네킹, 카운터 등 독립된 집기. 종류의 공통 정의와 개별 배치 인스턴스를 분리한다.
- `placements`: 집기 위 상품·POP의 위치와 방향. 제공되지 않은 SKU, 재고, 실측 높이를 생성하지 않는다.
- `cameraPresets`: 주요 존의 중심·범위와 검토된 시점. 기본 시점을 막는 기둥·집기 때문에 필요할 때만 대상별 보정을 둔다.
- `qualityContract`: 매장 고유 특징, 필요한 상호작용, 기하 예산, 캡처 시점과 실패 조건. 주택 데모의 숫자를 공통 하한·상한으로 복사하지 않는다.

위 항목은 공용 의미 규약이다. 포함된 `img2-house` 검증기가 `store-spec.json`을 읽거나 이 항목을 검사하는 것은 아니다.

## 반드시 유지할 교훈

도면 원본과 화면 축소본의 좌표계를 구분한다. 사진의 그림자를 재질 색으로 옮기지 않는다. 개구부를 불투명 벽 위의 장식으로만 표현하지 않는다. 카메라 목표 거리는 컨트롤 한계와 일치시킨다. 선택 성공과 대상이 보이는 것은 따로 검사한다. 메시 병합은 이동·가시성·선택 단위를 보존한다. 상태 파일은 증거의 색인이며 렌더나 실제 조작을 대신하지 않는다.

## 유지보수

검증된 문제 → 관찰 값 또는 캡처 → 원인 → 수정 → 재검증 순으로 해당 reference 문서에 반영한다. 도면 파일, 특정 매장 좌표, 사용자 계정·호스트 설정은 공용 스킬에 넣지 않는다. 다른 매장에 아직 적용하지 않은 규칙은 검증된 사실로 승격하지 않는다.
