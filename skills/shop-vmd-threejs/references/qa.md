# 매장 VMD · 브라우저 검증

## 매장에 적용할 검증 기준

아래 항목은 공용 매장 검토 기준이다. 기존 주택 플러그인이 자동 검사하는 항목과 구분하고 프로젝트에 실제 구현한 기능만 완료 표시한다.

| 검증 대상 | 실제 확인할 내용 |
|---|---|
| 도면 | 좌표축·scale·출입구 방향, 내측/외측 치수, 전체 윤곽과 존 인접 관계 |
| 건축 구조 | 문·쇼윈도의 실제 개구부, 벽·기둥·천장 접합, 누락된 뒷면 |
| 집기 | 종류·위치·회전·크기, 바닥 접촉, 중복 또는 누락, 선반 단수 |
| 진열 | 지지면 접촉, 관통·부유, 상품 정면, 제공된 수량·배치 규칙 |
| 동선 | 출입구·계산대·피팅룸 접근을 막는 배치, 지정된 통로 폭 |
| 선택 | 존·집기 ID 일치, raycast와 DOM 목록 일치, 선택 대상의 화면 내 가시성 |
| 보기 | 전체·실내·평면·절개의 실제 차이, 돌아왔을 때 원래 상태 복원 |

통로 폭은 사용자·설계 자료의 기준과 비교한다. 임의 값을 법규나 접근성 인증 기준으로 제시하지 않는다. 배치 편집이 범위에 없다면 편집기·저장·undo를 검증 요구로 추가하지 않는다. 편집 기능을 구현했다면 이동·회전·초기화·저장/복원과 ID 유지까지 검사한다.

## 실제 브라우저 시나리오

프로덕션 빌드에서 페이지 준비 상태를 기다린 뒤 검사한다. 고정된 sleep만으로 완료를 가정하지 말고 카메라와 장면 상태를 확인한다.

1. 실제 WebGL 렌더, 오류 로그, 유한한 좌표·양의 bounds·예산을 확인한다.
2. 모든 존과 주요 집기를 선택하고 이름·하이라이트·최종 가시성을 확인한다. 가려진 대상을 보여주는 시점인지 스크린샷을 직접 본다.
3. 드래그·줌과 클릭을 구분하고 최소/최대 줌에서도 이동이 끝나는지 확인한다.
4. 보기 전환과 초기화를 반복한다. 절개 상태의 천장·벽·조명 복원이 누락되지 않아야 한다.
5. 제공된 조명 모드별 글자 대비와 실내 가시성을 검사한다.
6. 도면/참고 자료의 열기·소스 전환·닫기·Escape·focus 복원을 확인한다.
7. 375·768·1280px를 기본 검토 폭으로 삼고 실제 대상 기기에 맞춰 추가한다. 패널 겹침, 가로 overflow, 한국어 줄바꿈과 focus를 확인한다.
8. reduced motion, 창 크기 변경, WebGL 미지원·context loss 상태를 검증한다.

## 캡처와 증거

평면, 입구, 후면·좌우 또는 대응 내부 시점, 전체 보기, 모든 선택 프리셋, 모바일, 조명, 모달과 실패 상태를 목록화한다. 기준 카메라와 보조 카메라를 구분한다. 3D 매장과 2D 도면, 서로 다른 목적의 참고 사이트를 억지로 픽셀 일치 점수로 비교하지 않는다.

각 캡처에 `view`, 상대 경로, SHA256, viewport, 보기/선택 상태를 기록한다. 모든 소스·사양·참조 입력·관련 에셋과 빌드 설정을 증거에 연결한다. 스크린샷 형식·크기·해시 검증과 사람이 내용·가림을 판단하는 검토는 별개다. 버전별 상위 몇 장만 해시로 묶고 나머지를 같은 수준의 증거라고 부르지 않는다.

소스 변경 후 기존 캡처의 해시만 갱신해서 승인하지 않는다. 영향받는 화면을 다시 캡처하고 최종 인계 시 동일한 빌드의 완전한 증거 묶음을 확인한다. 새 파일·삭제된 파일·바뀐 에셋도 오래된 QA를 무효화할 수 있다.

여러 구현자가 작업하는 경우 최종 캡처 시작 전에 소스와 빌드를 동결하고, 시작·종료 시 입력 파일 목록과 해시를 비교한다. QA 스크립트 변경도 기록하되 제품 수정과 증거 수집 수정은 구분한다. 카메라 정착과 CSS 색상 전환 완료는 다른 조건이다. 정적 캡처는 둘 다 기다리고, 모션 검토용 중간 프레임은 별도로 캡처한다.

성능 측정 중 다른 에이전트의 브라우저 렌더·빌드를 동시에 돌리지 않는다. 단일 측정값으로 결론내리지 말고 동일 빌드·브라우저·스로틀 조건의 반복 결과와 첫 로드/후속 로드 차이를 보존한다. CPU 경합이나 소스 변경이 있었던 결과를 최종 점수로 사용하지 않는다.

## 판단과 수정

수정 범주는 좌표/카메라 → 구조 → 집기/상세 → 재질/조명 → UI/상호작용 순으로 분리한다. 가림 문제를 재질 변경으로 숨기거나 치수 오류를 카메라 원근으로 덮지 않는다. 반복 실패가 자료의 모호함 때문이면 그 한계를 구체적으로 기록한다.

중요한 UI 작업은 구현자 외의 검토자가 최신 캡처와 실제 소스를 확인한다. 기하/행동 검사가 통과해도 사람이 보는 선택 대상이 안 보이면 실패다. 반대로 예쁜 화면만으로 정확한 치수나 올바른 식별자·리셋 동작을 인증하지 않는다.

결과에는 구현한 범위, 측정 조건, 통과·실패·미검증 항목을 따로 적는다. 실측하지 않은 성능 점수, 법규 적합성, 제품 정확성은 주장하지 않는다. 기능·시각 검토와 모바일 초기화 성능은 각각 보고한다.
