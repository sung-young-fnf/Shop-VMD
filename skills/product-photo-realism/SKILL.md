# 실제 상품 사진 기반 질감·실사 표현

실제 상품의 색, 로고, 프린트, 원단과 주름을 사진에서 보존하여 매장 Three.js에 적용한다. 검증된 기본 경로는 **의류 사진 기반 2.5D**다. 모자·신발에는 자료와 형태에 맞게 별도 검증하며, 의류의 성공을 다른 카테고리의 성공으로 간주하지 않는다.

## 표현 방식 선택

- 사진과 같은 외관이 우선이고 매장 진열 감상이 목적이면: 실제 사진 + 윤곽 기반 얕은 입체 표면을 우선 평가한다.
- 조명 변화, 실제 측면 구조, 착용·변형이 필요하면: 검증된 의류 메시와 적절한 UV/PBR 자료가 필요하다. 사진 투영만으로 충족한다고 보고하지 않는다.
- 한 장만 있으면: 보이는 면만 근거가 있다. 뒷면 로고·절개선을 창작하지 않고 미확인 또는 추정 면으로 구분한다.
- 앞·뒷면 사진이 있어도 측면과 두께는 자동으로 복원되지 않는다. `photo-textured 2.5D; captured lighting, inferred depth`처럼 표현 경계를 남긴다.

## 실제로 잘 보이는 이유

사진에는 원단 결, 자수, 주름, 촬영 조명과 그림자가 이미 들어 있다. 이를 생성 텍스처로 다시 그리지 않고 보존하면 원상품과의 시각적 일치가 좋아진다. 윤곽과 완만한 두께는 회전 시 평면 카드 느낌을 줄이지만, 실제 봉제 패턴이나 물성을 복원한 것은 아니다.

## 작업 절차

1. **원본 확인**: 사람이 없는 상품 단독 컷을 직접 열어 본다. 같은 SKU·색상인지 확인하고 앞/뒤/디테일 역할, 해상도, 투명도, 출처와 해시를 기록한다. 다른 색상 사진을 섞거나 낮은 해상도를 원본 고해상도로 주장하지 않는다. 원본은 보존하고 파생 파일을 분리한다.
2. **일치 기준 선정**: 로고 방향, 문구, 소매 패치, 넥 배색, 밑단과 실루엣 등 해당 상품의 식별점을 정한다. 처음에는 대표 SKU 하나를 검증한 후 확장한다.
3. **사진 좌표와 윤곽 맞춤**: 이미지 픽셀 좌표, 분석용 축소 좌표, UV와 월드 좌표를 명시적으로 연결한다. 알파 윤곽을 추적하되 촬영 그림자를 옷으로 포함하지 않았는지 직접 확인한다. 검은 원단을 그림자로 지우지 않도록 임계값을 상품별로 검토한다.
4. **형상 구성**: 윤곽 내부를 삼각분할하고 완만한 볼륨을 준다. 앞·뒤 표면, 측면 벽과 내부 바탕면을 구분한다. 실제 치수가 없으면 크기·두께는 추정으로 기록한다.
5. **사진 재질 구성**: 촬영 외관 보존 모드에서는 sRGB 텍스처와 `MeshBasicMaterial`, `toneMapped: false`를 출발점으로 사용한다. 기존 렌더러의 색 관리와 후처리 결과를 함께 확인한다. 로고를 재생성하거나 밝기만으로 normal/roughness를 만들지 않는다.
6. **앞·뒤 및 경계 봉합**: 비대칭 윤곽의 XY 위치를 유지하면서 뒷면을 구성한다. UV 방향과 외측 법선을 확인한다. 사진 알파와 실제 구멍을 구분하고 내부 바탕면이 프린트를 가리지 않게 한다. 구현 전 [경계·재질 세부 규칙](references/garment-photo-surface.md)을 읽는다.
7. **매장 통합**: 기존 배치·행거·SKU 식별자를 유지한다. 메시·텍스처·재질을 재사용하고 전체 상품에 고해상도 파일을 무조건 적용하지 않는다. 진단 코드가 Basic/Standard 재질 모두의 실제 로딩 상태를 집계하게 한다.
8. **검증**: 아래 완료 조건을 실제 렌더와 조작으로 확인하고 현재 빌드에 연결된 증거를 저장한다. 개발/운영 경계는 프로젝트 지침을 따르며 문서화나 개발 성공이 운영 반영 권한을 의미하지 않는다.

## 완료 조건

- 원본과 렌더를 비교해 문구, 로고 좌우 방향, 배색, 소매·밑단의 식별점이 유지된다. 원본 복사를 표방한 에셋은 바이트 해시도 일치한다.
- 앞, 뒤, 앞 사선, 뒤 사선, 측면에서 배경 틈·프린트 가림·부유 사진·윤곽 불일치가 없다. 검증은 실제 회전·확대도 포함한다.
- 텍스처 로딩·셰이더 준비 이후 캡처한다. `ready` 플래그나 메시 개수만으로 성공 처리하지 않고 실제 상품이 그려졌는지 확인한다.
- 적용 매장에서도 근거리/원거리, 작은/큰 화면, 해당 앱의 조명·이동 모드를 확인한다. 단독 뷰어 성공을 매장 통합 성공으로 대체하지 않는다.
- 오류·WebGL context loss가 발생한 실행은 기록을 남긴다. 재시도 성공을 지속 안정성이나 GPU 문제 해결로 주장하지 않는다.
- 무엇이 실제 사진이고 무엇이 추정 형상인지, 이번에 검증한 SKU와 제외한 카테고리를 결과에 명시한다. PBR·360도·img2 하네스의 미실행 게이트를 완료로 표시하지 않는다.

## 재사용 근거

모자·신발처럼 곡면이 중요한 상품을 수정할 때는 [다중 사진 투영과 연결부](references/accessory-photo-surfaces.md)를 읽는다. 여기에는 재현된 실패 원인과 검증 기준을 기록하며, 진행 중인 구현을 성공 사례로 간주하지 않는다.

이 저장소의 첫 의류 적용은 [검증 사례와 코드 위치](references/garment-photo-surface.md#검증된-로컬-사례)에 기록되어 있다. 사례의 치수·색·윤곽 수를 다른 상품의 기본값으로 복사하지 않는다. 이 스킬은 원본 사진을 생성형 도구로 바꾸는 작업을 요구하지 않는다.
